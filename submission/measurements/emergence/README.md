# マルチLLM相互作用の創発 — 抽出結果

作成: 2026-08-30 / 抽出ツール: [`scripts/extract_emergence.js`](../../../scripts/extract_emergence.js)

指揮官LLM 1体 ＋ 艇LLM 3体（同一 system prompt・同一モデル）が同じ盤面で相互作用したログから、
**system prompt に書いていない振る舞い**だけを4種に限定して数えた。「創発を見た」と主観で
言わずに済むよう、指標はいずれも元ログの行に還元できる形にしてある。

| ファイル | 元ラン | エピソード数 | 艇の判断数 |
|---|---|---:|---:|
| [`emergence-qwen2.5-7b.md`](emergence-qwen2.5-7b.md) | qwen2.5:7b | 3 | 117 |
| [`emergence-qwen2.5-32b-1ep.md`](emergence-qwen2.5-32b-1ep.md) | qwen2.5:32b | 1 | 17 |

**サンプル数の制約を先に明示する**: どちらも少数エピソードであり、以下の所見は
「この規模で観測された」以上のことを主張しない。とくに所見2のモデル間差は
エピソード数が違う2ランの比較なので、**同条件反復で確かめていない**。

---

## 所見1 — 指揮官は指示されていない「標的の配分」と「艦種の対応づけ」を行う

指揮官プロンプト（`core/sim/command/commander_prompt.js`）は、**「1隻に1標的」「重複を避けろ」
「艦種を対応させろ」のいずれも要求していない**。全艇を最寄りの1隻に殺到させる采配も文法上は妥当に通る。

| 指標 | qwen2.5:7b | qwen2.5:32b |
|---|---|---|
| 全艇に相異なる標的を割り当てた采配 | 11/11 (100%) | 2/2 (100%) |
| 艦種が一致した個別指示（`def-heavy`→`int-heavy` 等） | 31/31 (**100%**) | 8/8 (**100%**) |

艇の id に艦種名が入っている（`def-scout` / `int-heavy`）だけで、モデルはそれを役割として読み、
同種同士を噛み合わせた。両モデルとも例外ゼロ。

## 所見2 — モデル規模を上げると「役割の分化」が現れる（本ランで最も強い差）

3体の艇は**同一の system prompt・同一モデル**で動く。違うのは置かれた位置と、そこから見える
レーダーだけ。それでも override 率（指揮官の命令に従わず自分で決めた割合）が割れた。

| 艇 | 艦種 | qwen2.5:7b | qwen2.5:32b |
|---|---|---:|---:|
| def-runner-1 | runner | 100.0% | **16.7%** |
| def-runner-2 | runner | 100.0% | **33.3%** |
| def-scout | scout | 100.0% | **80.0%** |

- **7b は全艇が毎回無条件に指揮官を無視した**（override 100%）。これは指揮系統が事実上機能していない状態で、
  「階層を作った」という設計上の主張が振る舞いとして裏づけられていない。
- **32b では索敵艇（scout）だけが頻繁に独自判断し、快速艇（runner）は概ね命令に従う。**
  指揮系統が機能した上での役割分化であり、位置と視界の違いだけからこの差が出ている。

## 所見3 — override は「反抗」と「再確認」に分かれる

同じ override でも意味が異なるため分離した。

- **反抗**: 指揮官が指定した標的と**別の標的**を選んだ
- **再確認**: **同じ標的**のまま、自前の新しい観測で取り直した

| | qwen2.5:7b | qwen2.5:32b (1ep) |
|---|---:|---:|
| 反抗 | 37 | 0 |
| 再確認 | 59 | 7 |

7b の反抗37件は、設計意図（`docs/system-design.md` の情報階層）が振る舞いとして現れた例である。
指揮官の統合図は数秒古く、艇は自分のレーダーで「今」を見ている。実例:

```
ep1 t=12.0s — def-runner-1
指揮官の命令 : intercept int-runner-1
艇の選択     : intercept int-heavy
艇の言い分   : closest threat
自艇レーダー : int-runner-1 が116m先、int-heavy が166m先 …
```

**注意（正直な留保）**: この例では艇が選んだ `int-heavy`（166m）は、指揮官が指定した
`int-runner-1`（116m）より**遠い**。艇は理由に "closest threat" と書いているが、自分のレーダー値と
矛盾している。つまり反抗そのものは起きているが、**その判断が正しいとは限らない**。
7b の override 100% と併せて読むと、7b の「反抗」の少なくとも一部は状況判断ではなく
出力の不安定さに由来する疑いがある。32b で override 率が下がり、かつ反抗が消えたことは
この解釈と整合する。

## 再現方法

```bash
node scripts/extract_emergence.js <calls.jsonl> --out <report.md> [--samples N]
```

`<calls.jsonl>` は `headless_run.js --llm-log` が書く LLM 呼び出しログ。
プロンプト本文・生の応答・レイテンシが1行1呼び出しで入っている。
