# 第 I 部 — 残りの実装計画

## 0. 進め方の原則

- **段階ごとに「動く全体」を通す。** 各フェーズの完了条件は必ず「1 コマンド／1 URL で確認できる」形にする。
- **フェーズ A（ルールベースのみ）を最優先。** LLM なしでゲームが成立・決着することが、
  以降すべての土台であり統制群になる。
- 推論品質の工夫（agent-io-design §4）は**フェーズ B 以降に 1 つずつ**。まとめて入れない。

## 1. フェーズ一覧

| フェーズ | 内容 | 完了条件（検証コマンド） |
|---|---|---|
| **A** | ゲームコア（LLM なし・完全決定論） | headless で全ルールベースの攻防が決着し、勝敗が散らばる |
| **B** | 防御側 LLM（指揮官＋艇） | ブラウザで `?blue=llm&boats=llm` が完走し、離脱・上書きがログに現れる |
| **C** | 計測 | 挙動指標つきの比較レポートが 1 コマンドで出る |
| **D** | 本番 GPU 移植 | クラスタで B/C が動き、腕あたりのエピソード数を増やせる |
| **E** | VLM（次段階） | 索敵艇のカメラ画像 → 識別台帳の書き込みが 1 本で繋がる |

# 第 II 部 — 実行環境の設計（手元 3060 と本番 GPU クラスタ）

## 6. 環境の対比

| | **開発環境（このPC）** | **本番環境（GPU クラスタ）** |
|---|---|---|
| ハード | RTX 3060 12GB | クラスタ（168GB 級） |
| 推論サーバー | Ollama（`http://localhost:11434/v1`） | vLLM 等（OpenAI 互換エンドポイント） |
| モデル | qwen2.5:7b / qwen2.5vl:7b（4bit） | Qwen3-VL-30B-A3B |
| アクセス | 手元 | **Mac PC から ssh**（確認済み） |
| 役割 | 実装・配線検証・小規模ラン | 大規模比較ラン・VLM・多腕スイープ |

## 7. 移植性の原理 — なぜ「差し替えるだけ」で済むのか

このリポジトリの 2 つの既存設計が、そのまま移植性の保証になっている。

1. **推論は OpenAI 互換 HTTP の向こう側にしかない。**
   コード側の環境差は `--llm-url` / `--model`（ブラウザは `?llm=` / `?model=`）の**設定値だけ**。
   環境ごとの if 分岐をコードに書かない（書きたくなったら設計の失敗と見なす）。
2. **シムの展開を決めるのは実測レイテンシではなく宣言値 `latencyS`**（[`time-model.md`](time-model.md)）。
   したがって**推論を速いマシンへ移してもシム結果は変わらない**。変わるのは実行に要する実時間だけ。
   「開発は手元・本番はクラスタ」と分けても実験の比較可能性が保たれる。

**環境差の正しい置き場所**は次の 3 つだけ:

| 差 | 置き場所 |
|---|---|
| エンドポイント・モデル名 | 起動フラグ / URL パラメータ |
| スループット（何体の decider を何秒間隔で回せるか） | `intervalS` 等の**宣言値**と腕あたりエピソード数 |
| 実測レイテンシ | **計測ドキュメント**（ルールに書き戻さない） |

## 8. 実行トポロジ — 2 通り

### T1: シムは手元、推論だけクラスタ（フェーズ B/C 向け・移植コストゼロ）

```
[このPC or Mac] シム(Node/ブラウザ) ──HTTP──> ssh トンネル ──> [クラスタ] vLLM
```

Mac から `ssh -L 8000:localhost:8000 <cluster>` でポートを手元へ引き、
`--llm-url http://localhost:8000/v1 --model <本番モデル名>` を渡すだけ。**コード変更なし**。
テキスト推論（LLM）はプロンプト数 KB なので回線負荷は無視できる。

### T2: 全部クラスタ（フェーズ D/E 向け）

```
[クラスタ] git clone → node で headless／puppeteer でブラウザ実験 → JSONL 回収
```

リポジトリはルート npm 依存ゼロ（Node だけで動く）。移植は clone のみ。
**VLM（フェーズ E）は T2 必須**: 判断のたびにレンダ画像が推論の入力になるため、
レンダリング（headless Chromium）を推論と同居させる（README の既存方針どおり。
分離する場合は転送時間を time-model §12.5 のステージとして宣言する）。

## 9. 移植の手順書（ランブック）

```bash
# 0. 手元: 未コミットの成果を push（master が 12 コミット遅れている点も解消する）
git add -A && git commit && git push

# 1. クラスタ側（Mac から ssh して）
git clone <repo> && cd asv_swarm_dt
node tests/core_smoke.test.js && node tests/command.test.js   # 依存ゼロで通るはず

# 2. 儀式: 新しい環境ではまず推論サーバーを単体計測する（設計より実測が先、の家訓）
node scripts/llm_probe.js --url http://<vllm>:8000/v1 --model <本番モデル名> --concurrency 1,2,4,6
#    → docs/llm-probe-measurements-<日付>.md に記録。
#    → この実測から intervalS・同時 decider 数・TIME_SCALE を決める（コードは変えない）

# 3. スモーク: 1 エピソードだけ LLM 腕で
node scripts/headless_run.js --scenario flag_defence_squadrons --episodes 1 \
  --blue llm --llm-url http://<vllm>:8000/v1 --model <本番モデル名> --llm-log probe.jsonl

# 4. 本番ラン: 腕あたりエピソード数を増やす（勝率分離には 1 腕 170 エピソード級が必要 = クラスタの出番）
```

## 10. 環境差の整理 — 何が同じで、何が違ってよいか

| 項目 | 環境間で | 保証のしくみ |
|---|---|---|
| シナリオ・ルール・宣言値 | **同一** | 設定ファイルと宣言値はリポジトリに入っている |
| 統制群（全ルールベース）の結果 | **バイト単位で同一** | 完全決定論（乱数・実時刻を使わない） |
| LLM 腕のシム時間上の意味 | **同一** | latencyS が宣言値だから |
| LLM 腕の判断内容 | **違ってよい**（7B と 30B は別の腕） | ログの meta に model 名が必ず入る。**モデル名は腕の識別子の一部**として扱い、環境をまたいだ「同じ腕」の比較をしない |
| 実行の実時間・回せる規模 | 違ってよい | 実測ドキュメントに記録。宣言値には書き戻さない |
| VRAM 起因の縮退 | 違ってよい | decision-architecture §6 の縮退順（interval 延長→間引き→1 隻だけ LLM）。すべて設定値 |

**一言でいえば: 環境の違いは「腕の名前」と「規模」にだけ現れ、ゲームの意味には現れない。**
これを破る変更（環境依存の if、実測値のルールへの書き戻し）を入れないことが、移植設計のすべてである。
