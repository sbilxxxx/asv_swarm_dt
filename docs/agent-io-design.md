# エージェント入出力設計 — 状況報告と命令、推論の質

> 作成: 2026-08-30 / v1
> 位置づけ: [`decision-architecture.md`](decision-architecture.md) の D1（エージェント）の入出力を定める正典。
> 「各エージェントは何を知らされ、何を言うのか」と「7B級でも推論が成立する形に問題を縮める工夫」。
> 用語: 本書以降、エージェントへの入力は**状況報告**と呼ぶ（旧称「視界」は視覚入力を連想させるため廃止。
> カメラ画像が入るのは VLM 段階の索敵艇だけである）。

---

## 0. 設計の芯 — 2 つ

1. **入力の設計とは「知っていることの食い違い」を意図的に作ること。**
   指揮官には広く古い情報を、艇には狭く新しい情報を渡す。役割分担はプロンプトの指示ではなく、
   渡す情報の差から自然に生まれる。
2. **推論の質は、モデルの賢さではなく問題の縮め方で決まる。**
   L0 の実測（LLM 指揮官は統制群に勝てず・同一命令の再送 80.9%）を「モデルが弱い」ではなく
   「問題の与え方が悪い」と読む。算数をコードへ移し、モデルには選択だけをさせる（§4）。

## 1. 各エージェントは何を知らされ、何を言うのか

### 1.1 指揮官

**知らされること**（10 秒に 1 回、副官が読み上げる戦況報告に相当）:

| # | 内容 | 性質 |
|---|---|---|
| 1 | 味方 4 隻の位置・針路・現在の任務 | 正確（味方だから） |
| 2 | レーダーが捉えた敵の位置 | 一件ずつ「何秒前の情報か」が添えられる。見失った敵は消える |
| 3 | 敵一件ずつの正体 | 「重装艇と判明済み」または「**正体不明**」と明記 |
| 4 | 旗の位置・残り時間 | — |
| 5 | 自分の判断リズム | 「10 秒ごとにしか命令できず、命令は 3 秒遅れて届く」 |

**言うこと** — 艇ごとの任務の割り当て。5 種類:

| 命令 | 意味 | 粒度 |
|---|---|---|
| 討て | この艇はこの敵に当たれ | 具体（敵 ID） |
| 見て来い | 正体不明のあれに近づいて確かめろ | 具体（敵 ID） |
| 出ろ | この地点へ移動せよ | **マス目座標**（§3） |
| 警戒せよ | この方面を見張れ | 抽象（方角） |
| 待て | 旗の手前で待機 | 抽象（距離） |

触れなかった艇は今の任務を続ける。

**思想**: 「正体不明」とはっきり告げるからこそ「見て来い」に価値が生まれる。
無知を隠した報告からは、無知を解消する行動が出ない。

### 1.2 現場の艇

**知らされること**（3 秒に 1 回、操舵室で自分の計器を見るのに相当）:

| # | 内容 | 性質 |
|---|---|---|
| 1 | 自分のこと | 位置・針路・速さ・**自分が何者か**（艦種・自分の爆薬の届く距離） |
| 2 | 指揮官から今受けている命令 | 艇の判断は白紙からではなく**命令への応答** |
| 3 | 自分のレーダーに今映っているもの | **すべて今この瞬間の情報**（古さの注釈が要らないこと自体が艇の強み）。近くまで寄った相手だけ正体つき |

全体図は渡さない。渡すと「小さい指揮官」が増えるだけで、二層に分けた意味が消える。
艇の値打ちは視野の狭さと引き換えの新しさにある。

**言うこと** — 命令への返答。3 種類＋修飾 1 つ:

| 応答 | 意味 |
|---|---|
| 続行 | このまま命令に従う（**これが第一級の応答**。変えないなら何も書き直させない） |
| 離脱 | この相手からは離れる |
| 目標変更 | 命令と違うが、こちらの敵に当たる |
| ＋「〜を避けながら」 | どの応答にも付けられる。避ける**相手の ID** を言う。避け方の幾何はコードが解く |

**思想**: 問いを「戦局をどうするか」ではなく「**この命令、今の状況でもまだ正しいか**」に絞る。

### 1.3 かみ合わない瞬間（この設計が作り出したい場面）

> 指揮官（10 秒前の情報で）「int-2 を討て」
> 艇（たった今、間近で確認）「int-2 は重装艇。私の爆薬が届く前に向こうの爆風に入る」
> ——指揮官はまだ知らない。次の報告まで最大 10 秒。**その間、正しく判断できるのは艇だけ。**

### 1.4 言わせないこと

| 誰に | 言わせない | 理由 |
|---|---|---|
| 指揮官 | 舵角・速度・細かい経由点の列 | 操船はコードの領分。**目標としての座標は言ってよい**（将棋の「7六」と同じ。§3） |
| 艇 | 行き先の座標・舵角 | 艇の判断は目標の選択まで |
| 両方 | 変える必要のない命令の再宣言 | 黙る＝現状維持を正式な応答にする（再送 80.9% への対策） |

## 2. 失敗の意味論

推論不達・パース不能・締切超過は、すべて「返答が来なかった」として扱い、世界は前の命令のまま進む。
**ルールベースでの代行はしない**（LLM の腕の成績にルールの采配が混ざる）。
ただし結末は必ず種別付きで数える（decision-architecture §5）。

## 3. 座標の方針 — マス目（将棋の符号）

運用領域を **100m 四方のマス目**に切り、座標は「E4」のような符号で言う。

| | 連続座標 `(417.3, -82.6)` | マス目 `E4` |
|---|---|---|
| モデルにとって | 連続値の演算（弱い） | 記号の操作（強い） |
| 検証 | 領域クランプ・数値混入の検出が要る | 符号表にあるか見るだけ |
| 精度 | 過剰（追従制御の到達半径は 30m） | 十分 |

- 状況報告の中の位置表記もマス目で統一する（「int-3 は G5、旗から東 4 マス」）。
- マス目 → 実座標の変換（マス中心の座標）はコードが行う。
- 追従制御・物理・判定は従来どおり連続座標で動く。マス目は**エージェントとの会話にだけ**現れる。

## 4. 推論の質を上げる工夫 — 候補リストと投入順

**前提となる掟**: L0 で、善意のプロンプト追加 1 行が再送率を 80.9%→98.3% へ悪化させた。
工夫は思いつくことに価値がなく、**1 変更ずつ入れて挙動指標で測る**ことにしか価値がない。
以下は「まとめて入れる仕様」ではなく「1 つずつ試す候補リスト」である（効くと考える順）。

| # | 工夫 | 内容 | コスト |
|---|---|---|---|
| ① | **算数の追放** | 距離・到達時間・「迎撃に間に合うか」をコードが先に計算し、**事実として報告に書く**。モデルの仕事を「計算」から「計算済みの選択肢から選ぶ」に変える | プロンプト生成側の実装のみ |
| ② | **緊急度順の提示** | 敵の一覧を、コードが計算した旗への到達時間の短い順に並べる。並び順が優先順位の推論を肩代わりする | ほぼゼロ |
| ③ | **差分の提示** | 「あなたは 10 秒前に○○を命じた。その後、間合いは 80m 縮まった／全く縮まっていない」を 1 行で書く。死んだ命令への直接の対策。履歴を積むのではなく差分 1 行に圧縮する | 小 |
| ④ | **マス目座標**（§3） | 連続値を記号にする | 小 |
| ⑤ | **JSON 強制** | 推論サーバーの構造化出力機能（Ollama の format 指定）で出力を JSON 形に強制。パース失敗という失敗カテゴリをほぼ消す | ほぼゼロ・**即入れてよい** |
| ⑥ | **温度を下げる** | 0.7 → 0.2〜0.3。判断の一貫性をばらつきより優先。実験の腕として比較 | ゼロ |
| ⑦ | 多数決 | 同じ判断を 3 回引いて多数決。品質は上がるが推論コスト 3 倍。GPU クラスタ側でのみ | 大 |

**測る指標**（decision-architecture §5 より）: 離脱と識別の一致率・pursue/disengage/switch 比率・
同一命令再送率・null 率の内訳。悪化したら即 revert。

### ①の具体像（最重要なので 1 例だけ）

> 悪い報告: 「int-2 は (410, 120)、速力 4 m/s、旗は (0, 0)」 ← 距離と時間の計算を丸投げ
>
> 良い報告: 「int-2: 旗まで**あと 107 秒**で到達。迎撃に間に合うのは **runner-2 だけ**」

「見るのは強く、測るのは弱い」（2026-08-14 VLM スモーク実測）と同じ構図。
弱い仕事（幾何・算術）を全部コード側へ引き取り、強い仕事（読解・選択）だけを残す。

## 5. 書式（付録）

書式は実装の詳細であり、本書の主題ではない。実装時の規約のみ:

- 入力: プレーンテキスト。位置は整数（マス目導入後は符号）。小数はモデルの注意を食うだけ。
- 出力: JSON 1 個。フェンス剥がしは既存パーサ（`extractFirstJsonObject`）を流用。⑤導入後は不要になる想定。
- 名簿検証: 指揮下にない艇・報告に載っていない敵への言及はパース時に落とす（既存 parse_orders と同じ第一の防壁）。
- 艇の返答には reason（10 語以内）を必須とする。説明のためではなく、
  「離脱の判断が識別情報に基づいていたか」をログで突き合わせるための計器。
